## ✅ Dodge Fixed!

I found the issue - dodge was calculating correctly but the message wasn't being displayed to the player!

### The Problem

The `CombatCalculator.ApplyDamage()` method was correctly:
1. Checking dodge skill
2. Reducing damage when dodge succeeded
3. Returning a `DamageResult` with the dodge message

**BUT** the GameTickService was:
- Using the reduced damage ✅
- **Ignoring the dodge message** ❌

### The Fix

**File:** `src/EliteMud.Server/GameTickService.cs`

Added dodge message display in **two locations**:

#### 1. When mobs fight back during PvE combat (line 387-397):
```csharp
// Mob fights back
var mobDamage = mob.Definition.Level + Random.Shared.Next(1, 5);
var mobDamageResult = CombatCalculator.ApplyDamage(attacker.Player, mobDamage);

// Show dodge message if dodged
if (mobDamageResult.Dodged && !string.IsNullOrEmpty(mobDamageResult.Message))
{
    await attacker.Session.SendLineAsync(mobDamageResult.Message, cancellationToken);
}
```

#### 2. When mobs attack helpless players (line 209-218):
```csharp
// Mob does damage
var mobDamage = mob.Definition.Level + Random.Shared.Next(1, 5);
var damageResult = CombatCalculator.ApplyDamage(victim.Player, mobDamage);

// Show dodge message if dodged
if (damageResult.Dodged && !string.IsNullOrEmpty(damageResult.Message))
{
    await victim.Session.SendLineAsync(damageResult.Message, cancellationToken);
}
```

### How Dodge Works (Reminder)

**Legacy Formula:** `(random(1, 250) + damage) < dodgeSkill`

**At 100% dodge skill:**
- Against 5 damage: `(1-250) + 5 = 6-255` must be < 100
  - Success range: 6-99 (94 out of 250 = **37.6% chance**)
- Against 20 damage: `(1-250) + 20 = 21-270` must be < 100
  - Success range: 21-99 (79 out of 250 = **31.6% chance**)

**Damage Reduction:** `2 × your level`
- Level 1: 2 damage reduction
- Level 10: 20 damage reduction
- Level 20: 40 damage reduction

## ✅ Concurrency Error Fixed!

I've fixed the concurrency exception that was happening when you quit. The problem was caused by a race condition between the auto-save timer and the quit handler.

### The Problem

When you quit:
1. **Auto-save timer** saves your character to the database
2. **Quit handler** tries to save again
3. Entity Framework detects the row was already modified → **Concurrency Exception**

### The Solution

**File:** `src/EliteMud.Data/Repositories/CharacterRepository.cs`

Added concurrency handling to `UpdateAsync`:

```csharp
public async Task UpdateAsync(Character character, CancellationToken cancellationToken = default)
{
    character.LastPlayed = DateTime.UtcNow;
    
    try
    {
        _context.Characters.Update(character);
        await _context.SaveChangesAsync(cancellationToken);
    }
    catch (DbUpdateConcurrencyException)
    {
        // Character was already saved by another process (auto-save)
        // Reload the entity and try again
        var entry = _context.Entry(character);
        await entry.ReloadAsync(cancellationToken);
        
        // Re-apply changes
        entry.CurrentValues.SetValues(character);
        await _context.SaveChangesAsync(cancellationToken);
    }
}
```

**How it works:**
1. Try to save normally
2. If concurrency exception occurs (row was modified):
   - Reload the entity from the database
   - Re-apply the changes
   - Save again

This ensures your character is saved properly even if the auto-save and quit handler collide.

## Fix Applied: Dead Player Attacking Bug

### Root Cause
Race condition between player commands (kick) and the combat tick system running concurrently. The combat tick captured a snapshot of fighting players, but if a player died from a kick command during the tick processing, they could still be processed even though they were dead.

### The Fix
Added defensive guards at the start of both `ProcessPlayerVsPlayerAttack` and `ProcessPlayerVsMobAttack` methods in `GameTickService.cs`:

**In `ProcessPlayerVsPlayerAttack` (line 261):**
```csharp
// Double-check that both players are still in fighting state
// (guards against race conditions with kick/kill commands)
if (attacker.Player.Position < Position.Fighting || attacker.Player.FightingConnectionId == null)
{
    return;
}

if (victim.Player.Position == Position.Dead)
{
    // Victim died (possibly from concurrent kick command)
    CombatCalculator.StopFighting(attacker.Player);
    return;
}
```

**In `ProcessPlayerVsMobAttack` (line 347):**
```csharp
// Double-check that player is still in fighting state
// (guards against race conditions with commands)
if (attacker.Player.Position < Position.Fighting || attacker.Player.FightingConnectionId == null)
{
    return;
}
```

### Why This Works
1. **Re-checks position**: Even if the attacker was in the snapshot, we verify they're still able to fight
2. **Re-checks FightingConnectionId**: Ensures combat wasn't stopped by a command
3. **Checks victim death**: In PvP, if victim died from a concurrent kick, we gracefully stop the attacker's combat

This creates a **defense-in-depth** approach where we check the fighting state at multiple points:
- Line 117: Initial position check (original)
- Line 123: FightingConnectionId null check (original)
- **NEW**: Re-check both at the start of the attack processing method
